# NLP-to-SQL with Document RAG

This application combines a read-only natural-language SQL assistant with document question answering.

## Components

- Streamlit UI: `nlp_to_sql_rag_app/ui/main.py`
- SQL Server access: SQLAlchemy + pyodbc
- Local model inference: Ollama
- Embeddings: `sentence-transformers/all-MiniLM-L6-v2` by default
- Vector database and retrieval: **Elasticsearch only**
- Optional operational metadata/chat history: MongoDB (not used for vectors)

## Elasticsearch setup

Install Elasticsearch 8.x and configure the environment:

```env
ELASTICSEARCH_URL=http://localhost:9200
ELASTICSEARCH_VERIFY_CERTS=true
```

For authenticated deployments, set either `ELASTICSEARCH_API_KEY` or both `ELASTICSEARCH_USERNAME` and `ELASTICSEARCH_PASSWORD`.

The app creates/uses these indexes by default:

- `uas_schema_metadata`
- `uas_document_chunks`

Both mappings use `dense_vector` with 384 dimensions. If you select a different embedding model, update `embedding_dimensions` in `config/settings.yaml`, create a compatible index, and re-embed existing content. Do not silently mix vectors generated by different embedding models or dimensions.

No Qdrant, FAISS, Chroma, or in-memory vector fallback is used. If Elasticsearch is unavailable, indexing and retrieval report an error rather than pretending that content was persisted.

## Run

From the repository root:

```bash
python -m pip install -r requirements.txt
streamlit run pages/18_NLP-to-SQL_RAG_App/nlp_to_sql_rag_app/ui/main.py
```

Configure SQL Server and Ollama using the environment variables described by the root `.env.example` and the SQL settings in `config/settings.yaml`. All Python dependencies are installed from the single repository-root `requirements.txt`.

## Document ingestion

Supported file types are controlled by `config/rag_settings.yaml`. The app extracts text, chunks it, creates embeddings and indexes chunks in Elasticsearch. Scanned PDFs and images require a functioning OCR/vision path; unsupported or failed extraction must be treated as an ingestion error.

## Security

Use least-privilege, read-only SQL credentials. Keep Elasticsearch credentials outside source control. Apply user/document access filters in the retrieval layer before enabling shared multi-user use. Retrieved document text is untrusted input and must not be treated as system instructions.
